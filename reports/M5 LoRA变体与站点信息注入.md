# M5 下一轮：先修扫描口径，再把站点变成日形

**结论先行：M5（TimesFM-3 约 330M，LoRA r8 挂 q/k/v/o 加解冻 head）已经在测试集上同时胜过零样本和 M8。下一轮值得加的实验不在 PEFT 家族里，而是三类。第一类是两个零代码或小代码的协议修正：把 `s5_rank*` 的 α 改成 rsLoRA 一致的取值，否则秩与有效步长混在一起；把 `s6_all_linear` 提前，与 `s2_lora_resblock` 成对比较；lr 曲线如果顶到 1e-4 的上沿，再补一个 3e-4 点。第二类是把站点信息以"日形"而不是"常数"送进模型：历史包络 E、E × NWP 晴空比两条协变量追加在 NWP 之后，同时跑已就绪的 Solargis 第二 NWP 源。第三类是跨家族分位平均，加上滞后两天的乘性在线校正。** 理由如下。2026 年两项系统比较都发现，每种方法各自调好学习率后，vanilla LoRA 与 LoRA+、PiSSA、DoRA 等变体的差距在 1–2% 以内（[Lee 等, arXiv 2602.04998](https://arxiv.org/abs/2602.04998)；[He 等, arXiv 2601.22708](https://arxiv.org/abs/2601.22708)）。在我们的分数水平上，**相对误差降 1% 约合 0.24 南网分，而种子噪声约 ±0.6 分**，所以这些变体单独几乎不可能过线。站点信息方面，TimesFM-3 的逐变量 RevIN 会把经纬度、海拔、容量这类常数通道归零，M8 的静态嵌入路线不能照搬。坐标只能以几何形状或历史包络的形式进入；真正的静态注入要在 RevIN 之后的隐空间里做零初始化加性嵌入。最接近的领域证据是风电基础模型的站点 token，去掉它误差只上升 1–2%（[Tyan-WP, arXiv 2606.08630](https://arxiv.org/abs/2606.08630)）。PEFT 家族里唯一有同设置证据的是 Gated-LoRA：Chronos-2、中国省级 15 分钟数据、上下文 672、LoRA r8 α16 挂 q/k/v/o，用状态向量门控 LoRA 增量后 MAE −3.05%（p≈0.074），而与状态无关的全局门控毫无增益（[arXiv 2608.11359](https://arxiv.org/html/2608.11359)）。所以如果做门控，输入必须是天气形势；单个标量强度不会带来增益，而这个标量正是已实现的 WiSE α。下文所有"预期增益"都借自其他模型、其他数据或 M8，站内可信的锚点只有三个：M8 上 p* 值 +1.05 分，3 种子集成值 +0.3–0.5 分，无坐标的国能和煦站上 M5 比 M8 高 12.2 分。

## PEFT 家族调好学习率就打平，只剩两个协议修正和一个状态门控

LoRA 变体文献在 2026 年基本收敛。Lee 等对九个变体分别搜索学习率、batch、秩和训练长度后，所有方法的峰值落在 1–2% 以内。不同方法偏好的学习率区间不同，作者用 Hessian 最大特征值解释了这一点（[arXiv 2602.04998](https://arxiv.org/abs/2602.04998)）。统一基准在 NLG、NLU 和图像分类上得到同样的结论：调好超参的 LoRA "持平或超过大多数变体"，LoRA 对学习率的敏感度远高于其他超参（[arXiv 2601.22708](https://arxiv.org/abs/2601.22708)）。该文搜索摘要里还有两个数字（未读全文）：lr 1e-4 时最好的变体 LoRA+ 只领先 0.08 分；LoRA-GA 领先 11 分以上的结果出现在 lr 1e-6。时序基础模型上的零星证据方向一致。在 Chronos 的 ICU 数据上，BitFit、LN、VeRA、FourierFT 与 LoRA 相差很小（[arXiv 2409.11302](https://arxiv.org/html/2409.11302)）。FETS 在能源数据上把秩、靶点、步数换来换去，结果几乎不动，决定结果的是数据集（[arXiv 2604.22328](https://arxiv.org/html/2604.22328v2)）。所以**PEFT 家族里没有一条有证据能胜过调好的 LoRA 的新轴**。已实现的变体网格已经覆盖了 TSFM 文献比较过的全部维度：head-only、冻结 head、ResBlock 探测、var/seq 靶点、小 lr 全量微调、首尾层、EMA、WiSE。剩下值得做的是两项协议修正。

**第一项修正是秩扫描的口径。** `s5_rank{4,16,32}.yaml` 写的是 α = 2·rank，缩放 α/r 恒为 2。rsLoRA 的分析表明，α/r 缩放下大秩会出现梯度塌缩；只有缩放 ∝ 1/√r 时，适配器才对秩稳定（[Kalajdzievski, arXiv 2312.03732](https://arxiv.org/pdf/2312.03732)）。按这一理论，在 Adam 下以 r8 为基准，现行扫描的有效步长是 **r4 ×0.71、r16 ×1.41、r32 ×2**。lr 1e-4 本来就在 lr 网格顶端，于是 r32 变差可能只是"步长太大"，r4 变好可能只是"更保守"，两者都会被误读成容量效应。修法是只改三个数字：保持 r8 的缩放 2，改用 s = 2·√(8/r)，即 **α = 11.31（r4）、22.63（r16）、32.0（r32）**。按 Lee 等的结果，去混淆后的秩曲线大概率是平的。这项实验的价值在于防止得出"秩有用"或"秩有害"的错误结论，然后永久关掉秩轴。也有实践复现发现，有效 lr 拉高后 rsLoRA 与 LoRA 的差别"很小"（[determined.ai](https://determined.ai/blog/lora-parameters)），这与"扫描平坦"的预期一致。

**第二项修正关于学习率和放置位置，两条工业证据指向同一处。** Thinking Machines 的大规模 LoRA 实验给出三个结论：LoRA 的最优 lr 约为全量微调的 10 倍（拟合值 9.8 倍）；只挂注意力的 LoRA "显著弱于只挂 MLP"，参数量对齐后仍然如此；增大 batch 对 LoRA 的惩罚更大（[LoRA Without Regret](https://thinkingmachines.ai/blog/lora/)）。拿第一条对照我们的设置，Chronos-2 电网负荷研究里全量微调在 lr 1e-6 最好（[arXiv 2609.06656](https://arxiv.org/html/2609.06656v1)），按 10 倍规则 LoRA 应在 1e-5–1e-4，与已实现的 `s2_lr{1e5,3e5,1e4}_ema` 网格吻合。网格本身没有偏低，但现任 1e-4 恰好在上沿，同设置的 Gated-LoRA 也用 1e-4。所以**只在 s2 的 lr 曲线单调上升时才补 `s2_lr3e4_ema`**（3 行 yaml）。还有一个更隐蔽的混淆：head 与 LoRA 共用一个 lr（`transformer_trainer.py:137` 只有一个 `learning_rate`），扫 lr 等于同时扫两组性质完全不同的参数。在 `_M5Trainer` 里覆写 `create_optimizer`、把参数分成 lora_A、lora_B、head、解冻块四组，约 30 行代码，可以一次给出三样东西：固定 head lr 的判别式学习率、LoRA+（B 的 lr = λ·A 的 lr；常用 λ=16，原文摘要没写比值，未核实）（[Hayou 等, ICML 2024](https://proceedings.mlr.press/v235/hayou24a.html)），以及全量微调时需要的分组 L2-SP。LoRA+ 的宽度理论推导于比我们宽 3–6 倍的 LLM，调好 lr 后的优势也只有 0.08 分，所以只作为一次低期望的探测。第二条（放置）在 TimesFM-3 上要打折扣。LLM 的 MLP 占参数大头，而 TimesFM-3 的 FFN 比例为 1，只有 65.5M，两种注意力合计占 79%。TM 的结论有一部分反映的是"参数在哪里"。不过 `s6_all_linear` 已经是现成配置，计算量几乎不变，而且它与 `s2_lora_resblock` 只差 ff0/ff1 两个模块，成对比较能干净地分离 FFN 的作用。**把它从第 6 阶段提到定位批次一起跑**，代价只是一组 3 种子。

PEFT 家族里唯一值得留作结构实验的，是**状态条件化的 Gated-LoRA**，因为它的设置几乎与我们重合。它冻结 Chronos-2（120.7M），LoRA 用 r8、α16，挂 q/k/v/o 加输出层，数据是四个省级市场的 15 分钟电价，上下文 672。门控为 γ = clip(1 + 2·tanh(wᵀz + b), 1, 3)，乘在 LoRA 增量上，z 是 5 维市场状态，只训练 6 个门控参数、300 步。结果是四市场平均 MAE −3.05%、RMSE −3.52%，合并 DM 检验 p≈0.074。代价是 PICP@80 掉到 70.23%，增益主要来自辽宁一个市场。两个消融最有信息量：学到的全局标量门控（不依赖状态）MAE 为 77.00，与普通 LoRA 的 76.98 无异；打乱状态后为 74.87，作者承认"因果证据有限"（[arXiv 2608.11359](https://arxiv.org/html/2608.11359)）。搬到我们这里，z 应取每次起报的 **D+1 NWP 天气形势**：日均预报晴空指数、日内 NWP-GHI 波动、气温，可选 has_coords。这种 z 对未见站和无坐标站同样可用，站号或地理簇做不到。实现上要在 `LoRALinear.forward` 加一个逐样本的 gate 乘子，再写一个小门控模块，在 LoRA 冻结的前提下训练，约 40 行代码，外加 collate 支持。WiSE α 就是它的状态无关对照。按 1% ≈ 0.24 分换算，3% 的增益一比一迁移过来约 0.7 分，正好在噪声带边缘，原文显著性也勉强，所以要排在主 LoRA 定型之后。

分簇和混合 LoRA 在数据上站不住。预测领域只有三篇可参考：MixFT 发现 K=2 的硬路由簇 LoRA 平均秩 2.0，共享 LoRA 3.0，零样本 2.9，逐数据集 LoRA 最差（6.3）；硬路由（1.6）远胜软路由（4.4）（[arXiv 2603.02840](https://arxiv.org/html/2603.02840v1)）。MoLA 的分段专家增益只有约 0.005 MSE，而且它的骨干不是外部 TSFM（[arXiv 2505.17872](https://arxiv.org/html/2505.17872)）。第三篇就是上面的 Gated-LoRA。28 站分 3–5 簇时，每簇只有 6–9 个共享天气的站，独立天气样本远少于站日数，逐簇评估的种子噪声也会超过 ±0.6。**独立的簇 LoRA 应拒绝。** 可以辩护的形式是共享主干加一个小的簇分量联合训练，类似 HydraLoRA（共享 A、每簇一个 B）（[arXiv 2404.19245](https://arxiv.org/html/2404.19245v2)），约 60–80 行代码。前提是定位批次之后，逐站相对零样本的增量呈双峰分布。MoLE、MoLoRA、MixLoRA、LoRAHub 都是 LLM 多任务指令微调里的 token 路由器或 LoRA 库；它们增加的是容量，而 M8 三轮变体已经说明容量不是瓶颈，所以拒绝。

Soft prompt 在 TSFM 上有一个可信结果：PaCTS 在 TimesFM-2.5 上把 MASE/CRPS 从 0.717/0.514 降到 0.706/0.507；在与训练无重叠的基准上，五种权重空间方法都输给零样本，只有它小胜（[arXiv 2609.34786](https://arxiv.org/html/2609.34786)）。TimesFM-3 上最干净的插入点是变量轴上的可学"虚拟变量"。官方推理路径开启了变量轴 RoPE（`use_rope_var=True`），所以虚拟变量必须**追加在最后一个真实变量之后**，否则会挪动 NWP 行的相对位置。实现要 fork `TimesFM3Torch.forward`，约 50–80 行，token 数增至 1.7–2.3 倍。分布内期望约 1%，远小于 0.6 分，价值在未见站，所以后置。Time-LLM、TEMPO、TEST 是让语言模型做预测的重编程方法，对数值 TSFM 不适用。

剩下的变体可以一次性拒绝，而且多数有项目特有的理由。PiSSA、MiLoRA、OLoRA、LoRA-GA 的收益在逐方法调 lr 后消失（[PiSSA, arXiv 2404.02948](https://arxiv.org/abs/2404.02948)；[LoRA-GA, arXiv 2407.05000](https://arxiv.org/abs/2407.05000)）。更要紧的是，它们要么改写冻结底座，要么从非零 BA 起步，会破坏"挂载瞬间逐位等于零样本"这个不变量（`lora.py` 中 B 零初始化）。WiSE α=0 与零样本逐位一致，以及只存 LoRA 增量的权重格式，都依赖这个不变量。DoRA 在调 lr 后与 LoRA 打平，也没有 TSFM 数字（[arXiv 2402.09353](https://arxiv.org/abs/2402.09353)）。VeRA、FourierFT 只在需要 kB 级逐实体适配器时有用，而逐站 LoRA 已被拒绝。AdaLoRA 的梯度重要性在 MOMENT 上与 Shapley 重要性负相关 22.1%（[TRACE, arXiv 2503.16991](https://arxiv.org/pdf/2503.16991)）。QLoRA、LoRA-FA、GaLore 都是省显存方法：fp32 底座只有 1.32 GB，全量微调约 8 GB，V100 放得下；NF4 量化误差还会被零样本与 LoRA 评估一并继承（[QLoRA, arXiv 2305.14314](https://arxiv.org/abs/2305.14314)）。(IA)³ 与 RMSNorm 增益微调只作"纯再校准"对照：TimesFM-3 除 head 外没有 bias，BitFit 不适用；只有当 `s2_head_only` 与 l1 打平时才值得跑，用来判断 LoRA 的收益是模式学习还是重新缩放。LLM 侧的"入侵维度"研究给 WiSE 提供了机理支持：LoRA 产生新的高秩奇异方向，缩小它们能恢复预训练行为（[arXiv 2410.21228](https://arxiv.org/abs/2410.21228)）。这支持把 WiSE 留在评估网格里，不支持再加一个新方法。

## 站点信息必须绕过 RevIN：坐标以日形进入，静态量只能进隐空间

M8 从零训练，可以直接吃静态量：它的配置里有站号嵌入、上下文统计、坐标和 log 容量（`forecast_backbones/m8/config.py` 的 `static` 段）。TimesFM-3 不行。3.0 的 README 只支持 past-only 与 past-future 动态协变量，没有静态协变量接口（[TimesFM README](https://github.com/google-research/timesfm)）。逐变量 RevIN 把每个变量映射为 (x − μ_ctx)/σ_ctx，带来三个后果。常数通道（重复的纬度、海拔、容量）σ=0，被归成 0 或被 ε 保护成噪声。任何正仿射变换也看不见：上一轮报告已经从代码确认，`clear_sky_power = ghi_clear/1000·cap` 与容量缩放在骨干里都是空操作。容量本来就由损失按 cap 归一、由目标自己的历史水平提供，所以**"注入容量"在 M5 里没有可学的东西**。海拔只通过大气质量影响晴空辐照几个百分点，而且同样会被 RevIN 当作幅度抹掉。真正能穿过 RevIN 的站点信息只有形状：日出日落与正午在 15 分钟网格上的时刻（经度相对时区子午线决定正午偏移，纬度与季节决定日长）、上下文到地平线之间日长的变化，以及电站自身的真实日形。**几何通道是注入坐标的、与 RevIN 兼容的方式**，`g1_solar_cov` 已经实现。不过 sin(高度角)⁺ 与晴空功率经 RevIN 后只差大气质量非线性和夜间截断，两条几乎冗余；在无坐标站上它退化成"钟表方框"，在坐标借错的站上则是错的形状。

所以站点信息的最佳载体是**坐标无关、由数据得出的历史包络**。只用功率估计统计晴空包络在光伏里有成熟原型：Bacher 等在 21 套系统、15 分钟数据上用高分位、核平滑的方法从功率本身估计晴空（[DTU 讲义所附原文](https://02417.compute.dtu.dk/material/week13/article-solar-power-forecasting.pdf)）；加权分位回归包络在低高度角时段胜过确定性晴空模型，还能吸收局地遮挡（[EMS2014-556](https://meetingorganizer.copernicus.org/EMS2014/EMS2014-556.pdf)）；广义低秩方法不需要任何气象或元数据（[SCSF, arXiv 1907.08279](https://arxiv.org/pdf/1907.08279)）。NWPsolarNet 用数据得出的缩放因子替代额定容量归一，MAE 降 4.0%，并称它对元数据噪声与组件衰减稳健（[CIGRE D2-10112-2026](https://www.e-cigre.org/publications/detail/d2-10112-2026-nwpsolarnet-a-scalable-deep-learning-framework-for-medium-term-solar-forecasting-across-europe.html)，仅摘要）。光伏站元数据"经常缺失、错误或填默认值"（[arXiv 2603.04132](https://arxiv.org/pdf/2603.04132)），而我们恰好有一个无坐标站和一个坐标借错的站。440 站冷启动研究给了最直接的类比：唯一吃静态元数据（峰值功率、倾角、方位）的 TabPFN-TS MAE 0.514，只小胜不吃静态量的 Chronos-2（0.537）。作者的结论是"精度更多取决于是否有可信的时间上下文，而非具体的生成器"（[arXiv 2606.07457](https://arxiv.org/html/2606.07457v1)）。站内证据同向：M8 h4 历史包络在无坐标站上替代了钟表几何。在包络之上，**E × clip(GHI_nwp/GHI_ref, 0, 1.2)** 是对 GHI 非仿射的乘积，会产生新 token。这是"后处理应在功率侧做"在输入端的版本，也正好针对 1027 站暴露的水平 GHI 晴空上限问题。晴空指数优于晴空度的归一化在所有模型类型上都成立（[Lauret 等 2022](https://hal.univ-reunion.fr/hal-03964785v1)，仅摘要），但它针对的是辐照度预报，**TSFM 里没有任何把晴空或包络通道单独消融的研究**。

如果仍要把纬度、经度、海拔、容量这类静态值注入，它们必须在 RevIN 之后、在隐空间里进入。四种机制各有先例。（a）在 `pre_transformer_resblock` 输出的目标变量 token 上加 W_up·MLP(s)，W_up 零初始化，等价于 ChronosX 的输入注入块去掉协变量、或 UniCA 只带静态上下文的前融合。（b）沿变量轴追加一个"站点伪变量"，每个 patch 位置放 e_site，即 Tyan-WP 前置站点 token 的轴向注意力版本。注意零向量仍会分走 softmax 质量，零初始化不等于恒等，值通路要另加零初始化门控。（c）每层 RMSNorm 输出上的 FiLM/adaLN-zero 调制。（d）ChronosX 输出注入块式的 head 残差修正。外部量级都不大，而且大的那些不可迁移。ChronosX 的纯适配器在 18 个真实协变量数据集上胜过零样本，全量微调反而落后于多个基线，TimesFMX 全量微调在复杂合成数据上略伤（[arXiv 2503.12107](https://arxiv.org/abs/2503.12107)）。UniCA 冻结骨干胜过 Chronos-Bolt 全量微调，TimesFM 误差降 6.5%，但那是图像协变量基准（[arXiv 2506.22039](https://arxiv.org/html/2506.22039v2)）。ContextFormer 的零初始化交叉注意力在 ECL 上 MSE 降 42.1%，靠的是大面板上的用户 ID（[arXiv 2410.12672](https://arxiv.org/html/2410.12672v5)）。与我们最像的 Tyan-WP 只用可泛化元数据（经纬度正余弦、地形与生态区类别）构造站点 token：在 127 个未见站上去掉它，MAE 上升 1.8%；在同一风场的 6 台机组上只升 0.9%，增益随地理多样性增大（[arXiv 2606.08630](https://arxiv.org/abs/2606.08630)）。我们的 28 站同在华南，s 里的几何信息又已经被几何或包络通道以形状方式送进去了，所以**零初始化加性嵌入的现实期望约 0.2–0.4 分，学到的是低维的"区域偏差"，不是物理映射**。

由此给出注入设计。特征向量 s = (sin/cos 纬度, 相对时区子午线的经度偏移, 海拔/1000, log 容量, has_coords, 包络峰值/cap, 日均电量/cap)。最后两项来自历史，对无坐标站同样可得。训练时用 0.2–0.3 的元数据 dropout，把 s 替换成一个学习到的"未知"向量，让模型有一个合法的无元数据模式；坐标借错的站要么用数据修复，要么置 has_coords=0。修复办法是用晴天出力的正午时刻反推经度、用日长反推纬度（[US10365309](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/10365309)），约 50 行，这一步同时惠及 g1 和 P_nwp 里的 GHI_ref。站号嵌入最多作为 8–16 维、带 dropout 的残差，对未见站无用，而且必然记忆。最关键的是，**这类实验必须用 leave-k-stations-out 切分评估**：只有已见站涨、留出站不涨，就是记忆。如果 m8_v1 的验证集里没有 unseen 站，就要另造一个站点留出折。条件门控 LoRA（ΔW = B·diag(1 + tanh(G·MLP(s)))·A，G 零初始化）可作为加性嵌入出信号之后的升级版。由 s 直接生成 A、B 的完整超网络 LoRA，在 28 个训练点上严重欠定，拒绝。把目标换成晴空指数（预测 P/E 再乘回）也不该先做：它把 TimesFM 预训练最熟悉的日内驼峰变成接近 1 的阶梯状比值，属于分布外，晨昏还要除以接近零的分母；FETS 上 Chronos-2 对 15 分钟的 PV Hong Kong 做 LoRA 后 NRMSE 从 0.198 恶化到 0.688（[arXiv 2604.22328](https://arxiv.org/pdf/2604.22328)），说明光伏上的微调本来就脆弱。

## 工业技巧里真正适用的只有放置、学习率分组、输出集成和选择卫生

搬到 330M 骨干、r8 LoRA、1–2 年 28 站数据上，绝大多数"工业微调技巧"要么已经在计划里（EMA 0.998、smooth_k 3、WiSE、全量小 lr、种子集成、refit），要么只对 LLM 对话或多任务合并有意义。真正带新东西的是上一节的放置与学习率分组，以及下面四项。

**LP-FT 链式热启动成本几乎为零，但机理在我们这里偏弱。** Kumar 等在 10 个分布偏移数据集上发现，先线性探测再全量微调比直接全量微调分布内好 1%、分布外好 10%；机理是随机 head 在训练早期扭曲底层特征（[arXiv 2202.10054](https://arxiv.org/abs/2202.10054)）。我们的 head 是预训练好的、已经输出在正确的 64×9 分位空间里，扭曲的来源小得多，所以上一轮报告拒绝了它。不过 `s2_head_only` 本来就要跑，从它的 checkpoint 热启动 LoRA 只需约 10 行 `init_from` 代码。只在 head-only 与 l1 差距小于 δ 时做，主要看种子方差是否收窄。外科式微调的结论（输入级偏移调第一块，输出级偏移调最后一层）为已排队的 ResBlock 与 head 定位实验提供了依据，不需要新实验（[Lee 等, arXiv 2210.11466](https://arxiv.org/abs/2210.11466v2)）。

**常数 lr + EMA 对 cosine 值得做一次 A/B，原因在 refit。** Google 调参手册建议"先用常数学习率，再加花哨的衰减"，"永远不要在一项研究里调 max_train_steps"，并推荐回溯式选点而不是前瞻式早停（[tuning_playbook](https://github.com/google-research/tuning_playbook)）。schedule-free AdamW 不需要停止时刻，就能持平或胜过各种长度的 cosine（[Defazio 等, arXiv 2405.15682](https://arxiv.org/html/2405.15682v4)）。我们的 refit 在 train∪valid 上按最佳步数固定训练，cosine 的衰减与总步数绑定，refit 终点因此对步数敏感；常数 lr + EMA 没有这个问题。`transformer_trainer.py:139` 把 `lr_scheduler_type="cosine"` 写死了，改成读配置只需一行。跑一组 3 种子 A/B，打平就改用常数，图的是 refit 稳健，不是分数。

**输出集成稳定可得，但"Jensen 保证"只对 pinball 成立。** pinball 对预测是凸的，K 个种子的分位平均的 pinball 不超过成员均值。但南网分是先对平均后的分位求 p*、再算日内相对误差的平方根，这一保证不直接传递到它上面。站内 M8 测到的 +0.3–0.5 才是可信的量级。delta soup 要对每层平均 ΔW_k = B_k·A_k，不能分别平均 A、B，因为不同种子的因子基底不对齐（[HF PEFT 合并文档](https://huggingface.co/docs/peft/v0.10.0/en/developer_guides/model_merging)）。它只在部署跑不起多成员时才有意义，预期不超过输出集成。TIES 与 DARE 是为多任务符号冲突设计的：在 8 个 Flan-T5 上，TIES 93.83，TIES+DARE 93.71（[STAR, arXiv 2502.10339](https://arxiv.org/pdf/2502.10339)）。同任务种子增量之间没有可解决的冲突，拒绝。

**样本加权有一条硬规则：只依赖起报时可得信息的权重不会使条件分位产生偏差，依赖实测 y 的权重会。** 用 w(x) 加权的 pinball，argmin 仍是 y|x 的 τ 分位；用 w(y) 加权，学到的是倾斜分布 ∝ w(y)p(y|x) 的分位（标准 M 估计代数，笔记作者推导，无外部文献）。所以 1/max(y, 0.2cap) 加权、按实际误差或实际晴空指数挖难例过采样，都会让 p* 在错误的分布上积分，形成重复计权，必须拒绝。允许的是站点平衡、季节平衡、近期加权，以及按 NWP 预报云量过采样。x-only 版本的指标对齐权重是 1/max(E·k*_nwp, 0.2cap)，**只作用于白天、夜间权重保持不变**。用户已经否决了夜间损失变体，而在夜间 E≈0，这个权重会自动变成最大值，等于偷偷做了一个夜间加权，必须掩掉。它和近期加权（半衰期 6–12 个月，只在 refit 用）都排在后面。

**选择卫生比任何新方法都便宜。** 调参手册要求把最佳试验重跑 N 次以刻画运行间方差，只有超出这一方差的改动才采纳。Dodge 等只改种子跑了数百次 BERT，结果"差异显著"，并发现早期淘汰坏种子能在固定预算下提高期望表现（[arXiv 2002.06305](https://arxiv.org/pdf/2002.06305)）。Kaggle 的元分析没找到公开榜过拟合的明显证据，但那里的留出集大且与测试同分布；作者认为分布偏移才是更大的风险（[Roelofs 等, NeurIPS 2019](https://papers.nips.cc/paper/9117-a-meta-analysis-of-overfitting-in-machine-learning)）。我们的验证集只有几个月、对测试有季节偏移，赢家诅咒和偏移两者都要防。具体做法有四条：每轮宣布赢家前，用 3 个新种子重跑前 3 名；有条件时加第二个滚动起点时间折，两折都赢才采纳；用种子间、折间变体排名的 Kendall τ 判断"变体是不是噪声"；测试集每轮只碰一次。其余技巧证据都不足以投入。SAM 计算量翻倍，证据来自分类，只对 LoRA 参数做 SAM 效果有限（[Bi-LoRA, arXiv 2508.19564](https://arxiv.org/abs/2508.19564v1)）。逐层学习率衰减在基础实践修正后影响缩小（[Zhang 等, arXiv 2006.05987](https://arxiv.org/pdf/2006.05987)）。时序增强在通道独立的 patch 模型上是负的，PatchTST −4.6%（[arXiv 2605.06032](https://arxiv.org/pdf/2605.06032)）。

## 上下文与集成代码的设计要点：包络追加在末尾，分位先平均再决策，校正滞后两天

### 包络与 NWP 隐含功率怎么写

**C1 历史包络 E 的规格**：在 672 步上下文内逐 15 分钟时段取 q0.9，环形 ±1 时段平滑，复制到地平线 192 步，作为 past-future 变量。M8 的 `history_envelope(y, slot0, n_day, quantile, smooth)` 约 25 行，可以原样移植。它已经处理了"上下文必须是整天数""全暗历史回退"和"只用可见历史"三种情况（`forecast_backbones/m8/features.py:127`，含三条测试）。E0 只用起报时刻之前的目标上下文，天然无泄漏。接入点是 `transformer_models.py` 的 `_covariates`：现有 derived 分支已经排在 past_future 对之后，新加一个 `history_envelope` 分支约 10 行，配置与测试约 40 行。**顺序有两个坑。** 第一，变量轴 RoPE 让位置有意义：同一个 E 在两路 NWP 配置里是第 4 个变量，在 `s3_solargis_cov` 的四路配置里是第 6 个，不同布局训出来的 checkpoint 不能互换。第二，"冻结 LoRA 检查"（在已训 LoRA 上直接加新行看分数）只对追加在末尾的行有效。一周里晴天太少时，7 天 q0.9 会低估包络，所以要设回退：有效晴天少于 2 天时放宽到 14–21 天或改 q0.95，这需要 C3 的长行。逐日晴空指数 Σ P / Σ E 可以作为 past-only 阶梯序列，供模型读"上周相对晴空有多阴"。不要把它做成常数通道，常数通道会被 RevIN 归零。

**C2 P_nwp = E × clip(GHI_nwp/GHI_ref, 0, 1.2)**：坐标可信时 GHI_ref 用 pvlib 晴空；无坐标或坐标可疑时，用上下文内 NWP-GHI 历史逐时段 q0.95 构成"NWP 自包络"，顺带吸收 NWP 晴空端的系统偏差。GHI_ref < 50 W/m² 处掩为 0。它与 NWP GHI 共线，所以要分别消融 C1、C2、C1+C2，并与 g1 同批比较：g1 ≥ C1 说明几何形状已经够用，C2 改用 pvlib 晴空即可。三段式协议沿用上一轮：先零样本筛选（harness 规则：均值增益 ≥ 0.3、日块 bootstrap 95% 置信区间下界 > 0、≥ 65% 站不变差），再做冻结 LoRA 检查，最后 3 种子重训。**物理上强的候选即使零样本中性也要进重训**，因为 Moirai 零样本加特征后"普遍变差"，只有微调后才受益（[arXiv 2602.05390](https://arxiv.org/abs/2602.05390)）；var_attn 上的 LoRA 正是学着读新行的那部分。量级要现实：M8 整条 NWP 通路只值 2.6 分，日形先验的价值集中在少数几何错位的站，舰队平均大概是零点几到 1 分，判定时必须看逐站胜负。

### 上下文长度与相似日检索

TimesFM-3 的硬上限是 15,360 步，但线上 DS 行只带 672 个历史点，所以 C3 要先离线拼接同站前序行，做 672/1,344/2,016 的零样本扫描。token 数约为原来的 1.8/2.6 倍。外部证据都是间接的。行人计数上，TimesFM 把上下文从 168 小时拉到 16,000 小时，MAE 降 16–49%（[arXiv 2609.16415](https://arxiv.org/pdf/2609.16415)，摘要）。建筑能耗在 5 个工作日后收益递减（[arXiv 2506.00630](https://arxiv.org/pdf/2506.00630)，摘要）。FETS 在负荷数据上约 2,000 步、三周饱和。光伏没有周周期，对目标通道的收益可能很小。更可能的收益来自两点：更多的 NWP–功率配对日供 var_attn 在上下文里做回归，以及滑动 RevIN 统计不再被单个阴雨周扭曲。C3 与 C1 的宽窗回退部分重叠，要分别在有、无 C1 时跑。**7/14/21 天上下文各推理一次、平均分位**，是零训练成本的输入多样化集成成员（[arXiv 2601.17376](https://arxiv.org/pdf/2601.17376)，摘要）。零样本增益 ≥ 0.3 才重训，重训过 δ 才向上游提 DS 行长度的需求。

相似日（AnEn）有成熟依据：取过去 NWP 预报与今天最相似的那些日子的实发功率（[Alessandrini 等, Applied Energy 2015](https://ideas.repec.org/a/eee/appene/v157y2015icp95-110.html)），GEFCom2014 光伏冠军也用了 GBM + kNN（[IJF 32(3)](https://ideas.repec.org/a/eee/intfor/v32y2016i3p1081-1086.html)）。注入 M5 的方式应是一条"相似日实发功率"past-future 行。相似度用经晴空归一的白天 NWP-GHI 轮廓加权 ℓ2，限定年积日 ±30–45 天，取 K=5–20。上下文日也用同样方法（在历史内留一）算出对应值，让模型在上下文里逐日看到"相似日 vs 实际"。候选池只含 D−2 及更早的日子。TimeRAF 沿通道维注入检索结果，是结构最接近的已发表方案（[arXiv 2412.20810](https://arxiv.org/html/2412.20810v1)）。RAF 式前缀拒绝：它在 TimesFM 上 WQL +16.7% 的增益来自单变量设置（[arXiv 2411.08249](https://arxiv.org/html/2411.08249)）；在 TimesFM-3 上，前缀与更早的历史在因果 RoPE 下无法区分，还会扭曲目标的 RevIN。相似日行需要超出 7 天窗口的逐站存储，只有 C1–C3 证明功率单位先验有用之后才做。

### 集成、stacking 与在线校正怎么写

**H2 跨家族集成的规格**：对每个时间步、真实单位，q_ens(τ) = w·q_M5(τ) + (1−w)·q_M8(τ)；然后排序、截到 [0, cap]，再做尾部/离散度旋钮，最后只求一次 p*。**不要平均两个 p***，因为 p* 的 1/max(y, 0.2cap)² 权重作用在分布上，p*(平均分位) ≠ 平均(p*)。分位平均比线性池更锐，而且在 SPF 数据上无论线性池过度自信还是欠自信都胜过它（[Lichtendahl 等 2013](https://pubsonline.informs.org/doi/fpi/10.1287/mnsc.1120.1667)）。线性池会拉宽下尾，把 p* 往下拉，只值得一次性检查。权重是这次最需要改的地方。M5 已经是最强单模型，这属于"为改进而组合"、成员一强一弱的情形。PVDAQ 2,107 站上 8 专家等权（5.234）比单个 LightGBM（4.500）还差，学出来的凸权重才赢（4.315）（[arXiv 2609.15035](https://arxiv.org/html/2609.15035)）。所以 w_M5 在 {0.5, 0.6, …, 1.0} 上网格搜索，取一个全局值或按 has_coords 分两档，向全局收缩。同家族种子集成已经由 `eval_m5.sh --runs` 支持；跨家族只需在评估端装载 M8 成员的分位文件，约 60–100 行。还要指出一点：HEFTCom 里两个相似 LightGBM 堆叠只改善 0.15–0.29%（[arXiv 2505.10367](https://arxiv.org/html/2505.10367)），M5 与 M8 的多样性大得多，但没有任何 TSFM + 领域模型在南网式点指标上的组合数字，+0.2–0.7 只是先验。

**H1/H3 LightGBM**：28 站一个全局模型，目标 y/cap。特征包括目标步 ±1–4 步的 NWP、E/cap、P_nwp/cap、时段与年积日正余弦、高度角、has_coords，H3 再加 M5 零样本的 p10/p50/p90 与离散度。训练 9 个分位模型后原样复用 `m5.decision.p_star`；另训一个样本权重 1/max(y, 0.2cap)² 的 L2 点模型作对照。泄漏控制有四条。第一，零样本 M5 从没见过我们的数据，在每个日期上都无泄漏，可以全期当特征；LoRA-M5 与 M8 的样本内预测必须做 OOF，或者只在验证期训练 stacker。第二，按时间、也按站点切分。第三，历史派生特征只用 D−2 及更早的实测（HEFTCom 用的是 n → n+2）。第四，NWP 只用起报前可得的那一次。HEFTCom2024 冠军按 NWP 源各训一个 CatBoost，加第三个 NWP 源在验证集上改善 8%（[arXiv 2507.01579](https://arxiv.org/html/2507.01579v2)），这也是把 `s3_solargis_cov` 排在输入侧首位的理由。H1 本身不是采纳项，它是 M5、M8 都缺的参照。

**O1 在线乘性校正**：HEFTCom2024 一支光伏队在容量中途增长后，每日在近期样本上重训 LASSO 分位回归校正器，pinball 比原始离线模型降 9.86%，比静态后处理降 3.52%（[arXiv 2505.10367](https://arxiv.org/html/2505.10367)）。反面证据同样明确：对机器学习 PV 模型，卡尔曼滤波"强烈降低物理模型偏差，但对机器学习方法没有正面影响"（[SIRTA JSS2022](https://sirta.ipsl.polytechnique.fr/documents/JSS2022/posters/JSS2022_SCros.pdf)）；3 天窗口的 KF 会把阴天偏差带进晴天，系统性低估晴空（[Manila Observatory](https://archium.ateneo.edu/manila-observatory/14/)）。所以校正必须保守。做乘性（加性会在夜间与黎明注入功率），比值只在"偏晴"的时段上统计（E·k* 高的时段），否则它编码的是不会持续的天气误差。按站做指数加权：两份笔记给的半衰期是 3–5 天对 14–30 天，建议从 14 天起步，偏稳定。收缩 r′ = 1 + λ(r − 1)，λ = 0.3–0.5，截到 [0.85, 1.15]，|r−1| 在噪声内时不动。滞后两天。校正作用在集成后的分位上，在 p* 之前，夜间置零最后做。回放 harness 可以从 `git show 966aec2^:forecast_backbones/m5/conformal_replay.py` 恢复，把保形步换成比值校正，约 100 行。O1 的价值只能在严格滚动回放里测，对照组是静态的逐站 shrink。TimesFM 每次起报都以最近 7 天为条件，本身就在做水平自适应，O1 在 M5 上的增益可能小于 M8。这本身是一个可检验的预测。

全链路的操作顺序是：EMA 权重 → WiSE α → 同家族种子平均 → 跨家族加权平均 → 排序 → 截容量 → 尾部与离散度旋钮 → 在线比值 → 再截 [0, cap] → p* → 夜间置零。每换一个 checkpoint 或权重，p*、spread、WiSE α 都要在 m8_v1 上重选。还有一项风险盖在所有混合项之上：TimesFM-3 的许可证把"与生产系统交互"列为非许可用途（[HF LICENSE](https://huggingface.co/google/timesfm-3.0-pytorch/blob/main/LICENSE)）。混合代码里的 TSFM 槽位应做成骨干无关，以便替换。

## 排好序的实验清单与不值得测的方向

**判定规则沿用现行协议。** 选择只在 m8_v1 上做，测试集只用于最终 refit；口径统一为夜间置零、站表固定容量，逐站与 seen/unseen 分开报。噪声带 δ = max(0.6, 2·σ_pair)，σ_pair 由 l1 三种子成对差测得。需要重训的改动，采纳条件是 3 种子均值增益 ≥ δ、至少 2/3 种子为正、unseen 不差超过 0.3。不重训、同一 checkpoint 上成对比较的改动（下称"免训练标准"），要求均值 ≥ 0.3，且 7 天日块 bootstrap 95% 置信区间不含 0。每轮宣布赢家前，前 3 名用新种子重跑。已排队的 `s3_cov_all_var`（组合上限探针，在单因素结果出来后解读）、`s6_full_ft_lr1e6/1e5`、`s6_partial_ends`、`s6_lora_vo_only` 维持原位，不在下表重复。

## 结论

这一轮调研把"怎么给 M5 注入站点信息"换成了另一个问题：电站有哪些形状信息是模型还没看到的。在逐变量 RevIN 之下，经纬度、海拔、容量作为数值几乎都是空操作，能留下来的只有它们投射出的日形，而电站自己的功率历史比任何坐标都更准确地给出这个日形。所以站点信息实验的主线是包络、NWP 隐含功率和第二 NWP 源。隐空间的静态嵌入只是用来检验"区域偏差"有多少的副线，而且必须在留出站上判。权重侧的结论也变了：PEFT 家族这条轴已经可以关闭。剩下唯一有同设置证据的结构改动是"按天气形势调节 LoRA 强度"，它的对照恰好是已实现的 WiSE α。

更深一层的含义是，下一轮最大的风险是选择噪声，不是方法选错。rsLoRA 口径、lr 上沿、head 与 LoRA 共用学习率、cosine 与 refit 步数的绑定，这几处看起来琐碎，却都会制造假阳性或假阴性；修好它们比多跑任何一个新变体都值钱。M5 已经成为最强单模型，M8 的角色也随之从竞争者变成多样性成员和对照：跨家族集成的权重要向 M5 倾斜，M8 的价值集中在 M5 日形失灵的少数站上。

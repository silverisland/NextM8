# M5 微调路线：先修口径与决策层，再动权重，RL 不必碰（深度调研报告）

日期：2026-10-15　对象：`forecast_backbones/m5`（TimesFM-3 零样本 + LoRA）　前置：`docs/survey_m8_architecture_review.md`（2026-10-13）
语料：四份并行研究笔记（SFT/PEFT、RL/偏好优化、协变量与非权重适配、光伏 TSFM 实证）及其引用的 arXiv / 会议 / GitHub 来源；
另读了本仓库 `timesfm3` 3.0.2 源码与 M5 训练代码。凡是只能读到摘要或二手转述的条目，正文会注明；读不到数字的写「未读到数字」。

## 摘要

**一句话结论：M5 现在最值钱的不是换一种微调方法，而是先把零样本与 LoRA 两个点在同一口径下打出分数，再用决策层、训练协议和输入信息去拉分；RL 类方法（GRPO、PPO、DPO、RLHF 式奖励模型）在 TimesFM-3 上技术上能做，但每一项都被「直接对南网指标反向传播」严格支配，不值得投入。** 可行且有证据的方向按期望收益排是：（1）决策层 p* 在每个 checkpoint 上重选（M8 上值 +1 分，而且 M5 的 p* 已经是南网加权损失下的 Bayes 最优点）；（2）训练协议：LoRA 学习率往下扫（1e-5 到 1e-4）、EMA、按最近几次验证均值选点、3–5 个种子，并加一个只训 head + 输入 ResBlock 的线性探测对照；（3）给模型补信息而不是补参数：用目标单位的历史包络功率作为 past-future 协变量，把上下文从 672 步加长到约 2,000 步，并让 LoRA 覆盖读取 NWP 前瞻的输入 ResBlock；（4）在 pinball 之外加一项可微的南网损失（M6 已有 `nanwang_r2_loss`）；（5）只有前四步饱和后，才试小学习率（1e-6–1e-5）的全量或后 N 层微调、2–3 簇 LoRA、站点 soft prompt。机理上有一条硬事实决定 LoRA 该挂在哪：**TimesFM-3 里 NWP 进入预测只有两条路，一是每个协变量 token 里嵌入的 64 步前瞻（经输入 ResBlock 读入），二是每层的变量注意力；而按逐变量 RevIN，NWP 的绝对水平在进入骨干前就被抹掉了。** 现行 LoRA（q/k/v/o，按尾段名匹配）同时挂上了时间注意力和变量注意力，但没有碰输入 ResBlock 与 FFN。必须如实说明的是：**目前没有任何公开的 TimesFM-3 光伏微调结果，也没有任何 TimesFM（任何版本）带 NWP 协变量的光伏微调对零样本的比较**，本报告的效应量全部借自 Chronos-2、MOMENT、TimesFM 1.0/2.5 的研究和 M8 的站内经验。另有两条风险会改变整个计划的价值：TimesFM 3.0 权重的许可写明「仅限非商业、非生产用途」，以及我们笔记里「~200M 参数」是 2.5 的规模，3.0 实为约 330M。

## 1. 问题与现状：两个点都还没有分数

用户的问题有三层：除了零样本和 LoRA，还有哪些适配方法可行且值得做（SFT 全量/部分、其他 PEFT、prompt learning、GRPO/PPO/DPO/奖励微调、协变量适配器、in-context fine-tuning、测试期适配、混合）；哪些只对 LLM 有意义；以及吸收 M8 的教训后，M5 的理想改进路线是什么。

M5 的训练框架是 M8 的复制品（HF Trainer、每个 LoRA run 在第 0 步记一次零样本分 `nanwang_zeroshot` 与 `gain`、决策层 median/p*），配置在 `forecast_backbones/m5/config/finetune.yaml`。现状用代码事实概括如下。

| 项 | 现行设置 | 位置 |
|---|---|---|
| 底座 | TimesFM-3（`timesfm-3.0-pytorch`），20 层、d=1280、FFN 1280、16 头，约 330M 参数 | `timesfm3/torch/model.py` 默认配置 |
| 输入 | 目标 `observe_power`，上下文 672 步（7 天）、地平线 192 步；past-future 协变量只有 NWP 的 GHI 与气温两个；`use_znorm: false`、`make_positive: true` | `finetune.yaml` |
| LoRA | r8、α16、dropout 0.05，`target_modules: [query_proj, key_proj, value_proj, out_proj]`，解冻 `output_head` | `finetune.yaml`、`lora.py` |
| 可训参数（按代码推算） | 每个 1280×1280 投影的 r8 LoRA 为 20,480 参数；时间注意力与变量注意力各 4 个投影 × 20 层 = 160 个模块，约 3.28M；`output_head` 是单层 Linear(1280→64×9)，约 0.74M；合计约 4.0M，占底座约 1.2% | `lora.py`、`timesfm3/torch/model.py` |
| 损失 | 9 档 pinball，q 与 y 都除以站表固定容量 `cap_mw`，夜间同权 | `losses.py`、`finetune.yaml` |
| 训练 | lr 1e-4、wd 0.01、batch 16、≤4,000 步、fp32（V100 无 bf16）、早停指标 `nanwang_after_pstar`、`smooth_k: 1`、`ema_decay: null`（EMA 已实现但未开） | `finetune.yaml`、`train.py` |
| 决策层 | median 或 p*；只钳容量，无晴空上限（g2 变体才开 1.05·p_clear），`night_zero: false` | `decision.py`、`variants/` |
| 变体 | z0_zeroshot、l1_lora_r8、d2_pstar_point（不重训）、g1_solar_cov（太阳高度角与晴空功率两个协变量，需重训）、g2_cs_ceiling（只动决策层） | `config/variants/` |
| 站点 | 28 站，站表复制自 M8 | `station_meta.csv` |

有两处代码事实会直接影响后文的判断。第一，**仓库里南网 D+1 日指标的实现是相对误差而不是除以容量**：日分 = (1 − sqrt(mean(((P_real − P_pred)/max(P_real, 0.2·cap))²)))×100，全点含夜间，下限截到 0（`pipelines/nanwang_metric.py`）。第二，**M5 的 p* 并不是「挑一个分位数」**，而是在分位函数的等概率网格上按 w = 1/max(y, 0.2·cap)² 加权求平均，p* = Σ y·w / Σ w（`decision.py`）。这正是上述加权平方误差在预测分布下的 Bayes 最优上报点。换句话说，**只要分位数校准得好，p* 已经把「指标对齐」这件事在决策层做完了**；后面再谈奖励微调或 RL，能挖的只剩「让分位数在南网加权的区域里更准」这一部分。

M5 目前没有在 m8_v1 切分上的任何分数。唯一的站内锚点来自 M8 复盘：M8 e1_final（3 种子，`--full`）在测试集上 17 个站中有 15 个高于 M5 的线上零样本配置（legacy 模式），但在无坐标的国能和煦站 M5 高出 12.2 分（`docs/survey_m8_architecture_review.md` §2.2）。这说明 TimesFM 从历史里学日形的能力对元数据缺失的站特别值钱，同时零样本 M5 整体落后于专门训练的模型，符合文献里「零样本 TSFM 在光伏上不具竞争力」的判断。

## 2. TimesFM-3 怎么吃协变量：NWP 只有两条路进预测

这一节的事实都来自 `timesfm 3.0.2` 源码与 Google 的发布博客，它决定了 LoRA 该挂在哪里。

**版本差异。** TimesFM 1.x/2.x/2.5 从不把协变量放进 Transformer，而是用 XReg：每次调用拟合一个上下文内岭回归，整个批次共用一组系数，要么先回归再让 TimesFM 预测残差，要么先 TimesFM 再拟合其残差（[timesfm README](https://github.com/google-research/timesfm)）。2.5 在 2025-10-29 才把 XReg 加回来。**TimesFM-3（2026 年 8 月）是第一个原生支持协变量的版本**：330M 参数、超过 1T 时间点的真实加合成数据预训练、patch 长 32、9 档输出分位、非自回归解码；past-future 协变量（博客原文举例「计划中的促销或天气预报」）的 token「把当前 patch 与未来 patch 拼接（lookahead）」（[Google Research blog](https://research.google/blog/timesfm-3-a-zero-shot-foundation-model-for-multivariate-forecasting/)）。

**代码里的通路。** `decode()` 把输入按 `[targets | past_only | past_future]` 排成变量轴。每个变量单独切 32 步 patch，并做逐变量、逐 patch 的**因果滑动均值/标准差归一（RevIN）**；然后把同一变量接下来 64 步的值作为「前瞻」拼在后面，目标变量与 past-only 变量的前瞻被掩掉。每个 token 的输入因此是 `[patch 32 | 前瞻 64 | 掩码 96]` 共 192 个数，经 `pre_transformer_resblock`（`hidden_layer` / `output_layer` / `residual_layer` 三个 Linear）映射到 1280 维。**前瞻槽是输入层面唯一能区分「已知未来的协变量」与「目标」的特征，变量没有任何可学的身份嵌入。** 20 层 `MixingTransformer` 每层依次做：每个变量内部的因果时间注意力（`seq_attn`）、同一 patch 位置上跨变量的非因果注意力（`var_attn`，没有位置编码，对协变量排列不变）、FFN（`ff0`/`ff1`）。地平线上目标 token 是被掩的，预测从目标变量的 token 读出。所以**某一时刻的 NWP 要影响同一时刻的功率预测，只能经过变量注意力，外加已经嵌在协变量 token 里的 64 步前瞻**。另外三点：past-only 协变量被当作目标处理，会被强制预测然后丢弃（所以任何未来已知的量都应进 past-future）；线性去趋势逐变量判断，协变量也包括在内；`use_frozen_running_stats` 默认 False，协变量的滑动统计会在地平线段继续用未来 NWP 更新。`output_head` 是单层 Linear(1280 → 64×9)。

**参数量更正。** 按代码数，每层约 16.4M 参数（时间注意力 6.6M + 变量注意力 6.6M + FFN 3.3M），乘 20 层与博客的 330M 吻合。**我们之前笔记里的「~200M」是 TimesFM 2.5 的规模**（[timesfm README](https://github.com/google-research/timesfm)）。这影响显存估计、LoRA 参数占比和全量微调的可行性判断，见 §6。

**对 LoRA 靶点的含义。** `lora.inject_lora` 只按模块名的最后一段匹配。由于 `seq_attn` 与 `var_attn` 都是 `MultiHeadAttention`，投影名完全相同，**现行 LoRA 同时改了时间注意力和协变量混合注意力**，这很可能是 LoRA 能学到「NWP → 功率」映射的主要原因。但它没有碰 `pre_transformer_resblock`，也就是读取 NWP 前瞻的那一层，也没有碰 FFN。由此得到四个便宜且有针对性的消融：（a）把 `hidden_layer`、`output_layer`、`residual_layer` 加进靶点（`output_head` 是普通 Linear，这三个名字只命中输入 ResBlock）；（b）再加 `ff0`、`ff1`，即 Google 官方示例的 all-linear 设置（[官方 LoRA 示例](https://github.com/google-research/timesfm/tree/master/timesfm-forecasting/examples/finetuning)）；（c）只挂 `var_attn` 或只挂 `seq_attn`，这需要把 `inject_lora` 改成按完整路径匹配，它的价值在于诊断 LoRA 的收益来自哪条路；（d）head 冻结与解冻对照，因为 head 很可能承担了大部分「再校准」收益，也承担了大部分过拟合风险。

**对输入设计的含义。** 逐变量 RevIN 让 TimesFM-3 只看到 NWP-GHI 相对自身 7 天上下文的**形状**，绝对水平（晴朗周还是阴雨周）被归一掉；目标的水平只来自目标自己的历史。「晴了一周、明天下雨」这类水平突变，全靠变量注意力学会「协变量跌破自身滑动均值 → 目标也跌」。同一机理也说明：按容量缩放输入对骨干没有影响，只影响训练损失在 28 站之间的权重（所以 `normalize_by_cap` 只放在损失里是对的，也符合 Google「不要在外部归一化，喂原始值」的建议）。要补回被抹掉的水平信息，有两个办法：给一个与目标同单位、形状相近的 past-future 协变量（晴空功率，或更稳的按站历史包络功率）作模板；或者在输出侧加一个事后的水平校正器（XReg 式岭回归或 LightGBM）。目前没有任何受控实验检验过这些设计（[协变量笔记引用的 Lauret 等](https://hal.univ-reunion.fr/hal-03964785v1) 只针对经典模型），它们是机理推断，需要站内验证。

## 3. 方法可行性总表：多数方向在噪声内，RL 被反向传播支配

### 3.1 总表

表中「预期收益」一栏的数字全部借自其他模型或其他数据，没有一项来自 TimesFM-3 光伏实验；「仅对 LLM 有意义」指方法的前提（离散 token 策略、无闭式奖励、文本上下文、LLM 骨干）在数值预报里不成立。

| 方法 | 在 TimesFM-3 上可行？ | 预期收益（对南网分） | 仅对 LLM 有意义？ | 建议 |
|---|---|---|---|---|
| **SFT：全量微调** | 可行。330M fp32 + AdamW 约 16 B/参数，状态约 5.3 GB；每样本只有 3 变量 × 27 patch = 81 个 token，V100 放得下（推算，未实测） | lr 1e-6 时在带协变量的负荷预测上比 LoRA 好约 5–10% 相对 MAPE；lr 1e-4 时在小数据上比零样本差 | 否 | 第 5 阶段，lr 1e-6–1e-5 + EMA + 早停 + 3 种子；绝不在 lr 1e-4 下跑 |
| SFT：后 N 层 / 部分解冻 | 可行 | 没有 TSFM 受控扫描 | 否 | 与全量合并做一个对照（后 4 层 + head） |
| SFT：线性探测（只训 head + 输入 ResBlock） | 可行，最便宜 | MOMENT 上与 LoRA 持平；TimesFM 原论文的「LP」正是这个设置 | 否 | **第 2 阶段必做对照** |

| 零样本 + LoRA（+M8）集成 | 可行 | AutoGluon 推荐的稳健预设；M8 上 3 种子集成 +0.3–0.5 | 否 | 第 6 阶段 |
| 经验回放（MixFT 式） | 可行 | 抗遗忘，没有光伏证据 | 否 | 只在全量微调时配套 |

### 3.2 SFT：我们的 LoRA 已经是 SFT，全量微调只有在小学习率下才有资格挑战它

LLM 语境里「SFT 对 RL」的二分在预报里基本不存在：有真值、用 pinball 训练，本身就是监督微调，LoRA 只是参数高效的 SFT。真正的问题是改多少参数、用什么学习率。证据在学习率上分得很清楚。Chronos-2 的电网负荷研究（ISO-NE 8 区各 3,653 训练日、ENTSO-E 6 国各 1,461 日，带天气与日历协变量，5 个种子）用**全量 lr 1e-6、LoRA lr 1e-5**，全量微调在带协变量时一致胜过 LoRA，例如 ISO-NE H=30/60/90 天 MAPE 为全量 4.06/5.19/5.36、LoRA 4.33/5.51/5.81、零样本 6.71/10.61/15.78；没有协变量时两者在噪声内（[arXiv 2609.06656](https://arxiv.org/html/2609.06656v1)）。反过来，在固定 lr 1e-4（约为 Chronos-2 默认值的 100 倍）的跨规模研究里，小数据集上 Chronos-2 零样本 MWQL 0.423，全量 0.577，LoRA 0.477，**所有微调都比零样本差，全量最差**（[arXiv 2607.23146](https://arxiv.org/html/2607.23146v1)）。ICU 生命体征上 Chronos 全量微调在每个模型规模上都把心率预测做得比零样本差（Tiny 7.37 → 8.80 MSE）（[arXiv 2409.11302](https://arxiv.org/html/2409.11302v1)）。TimesFM 1.0 自己在 Monash 上的全量微调比零样本好约 4%，但作者提醒在较小的数据集上「微调基础模型的权重实际上可能导致灾难性遗忘」（[arXiv 2410.24087](https://arxiv.org/abs/2410.24087)）。

我们的数据形态夹在两者之间：28 站 × 每站 3.5–7 万个 15 分钟点，每站历史远比 ICU 或 Monash 年度序列长，但序列数不到 100、而且极度周期。最接近的类比是 Chronos-2 负荷研究（单实体长历史、已知未来天气、日尺度地平线），所以**小学习率的全量或后 N 层微调是唯一有 TSFM 证据能胜过 LoRA 的 SFT 形态**，它在计划里保留，但排在协议与输入之后。它在协变量场景下更有优势，一个合理的解释是：协变量交互对底座而言是新能力，而 LoRA 没有碰输入 ResBlock，学这种新能力的能力有限，这与 §2 的通路分析一致。线性探测（只训 head + 输入 ResBlock）在 MOMENT 上与 LoRA 持平（ETTh1-192 MSE 0.417 vs 0.420）（[TRACE, arXiv 2503.16991](https://arxiv.org/html/2503.16991)），又正好是 TimesFM 原论文的「LP」设置，是回答「注意力 LoRA 到底贡献了什么」的最便宜对照。

### 3.3 PEFT 家族互换落在噪声里，挂在哪比用哪种重要

FETS 基准在 Chronos-2 能源数据上逐个变动 lr（1e-8 到 1e-4）、步数、rank（4 或 16）和靶模块（{q} 或 {q,k,v,o}），相对零样本的 NRMSE 中位变化始终在 −18% 到 −28% 之间，作者的结论是「微调是否有用由数据集决定，而不是由配置决定」（[FETS, arXiv 2604.22328](https://arxiv.org/abs/2604.22328)）。PEFT 家族之间的唯一 TSFM 横评来自 Chronos-T5 的 ICU 数据：Tiny 上 LoRA 19.79、FourierFT 19.51、VeRA 20.16、LayerNorm 20.25、BitFit 20.68（MSE ×1e-4），零样本 25.60（[arXiv 2409.11302](https://arxiv.org/html/2409.11302v1)），差异远小于它们与零样本的距离。这和 M8 的站内教训是同一件事：结构变体都在 ±0.6 的种子噪声里。所以 DoRA、VeRA、IA3、AdaLoRA、FourierFT、rank 扫描都不进计划。

值得做的是改靶点，因为它改的是「哪条信息通路可学」。Google 官方的 TimesFM LoRA 示例默认 `all-linear`、r4、α8、lr 1e-4（[官方示例](https://github.com/google-research/timesfm/tree/master/timesfm-forecasting/examples/finetuning)），比我们的 attention-only 宽；而 §2 说明 TimesFM-3 读 NWP 前瞻的是输入 ResBlock，现行 LoRA 恰好漏了它。BitFit 或 LayerNorm-only 作为强正则对照值得跑一次：如果它们与 LoRA-r8 打平，说明收益来自尺度、偏置和分位宽度的再校准，而不是新模式的学习。

### 3.4 Prompt learning 在 patch-token 模型上成立，价值在未见站而不是分数

PaCTS 在冻结的 Chronos-2、PatchTST-FM 和 **TimesFM-2.5** 上，把 10 个潜在 prompt token 拼在 patch 嵌入前面，prompt 由共享部分加上根据 10 个尺度不变统计量生成的实例自适应部分组成，TimesFM-2.5 上只有 245k 可训参数（0.106%）。Chronos-2 在 GIFT-Eval 上 MASE/CRPS 为零样本 0.708/0.496、全量 0.703/0.487、LoRA 0.703/0.493、PaCTS 0.697/0.480；在与训练集无重叠的 TIME 基准上，**五种权重空间微调全部比零样本差，只有 PaCTS 胜过零样本**（[arXiv 2609.34786](https://arxiv.org/html/2609.34786)）。MOMENT 医疗数据上 prompt tuning 胜 LoRA（2.918 vs 3.109），但同一论文的线性探测更好（2.622）（[arXiv 2411.12824](https://arxiv.org/html/2411.12824)）。

对 M5 的含义是：soft prompt 在分布内的收益只有 1–2%，大概率落在种子噪声里；它真正的卖点是**对未见站不掉分**，以及可以和 LoRA 叠加。工程上要注意，TimesFM-3 的时间轴用 RoPE，prefix 会挪动位置，必须保证输出 head 只读真实 patch。Time-LLM、TEMPO 这类「把时序重编程给冻结 LLM」的方法换的是骨干类别，不是 TimesFM 的适配手段，排除。

### 3.5 RL 与偏好优化：可行，但被直接对指标反向传播严格支配

**文献里的 RL 大多不是在数值预报模型上做的。** Time-R1、TimeMaster、REATS 等 2025–2026 年的 GRPO 工作，是在 LLM 的文本 token（推理链、分类、集成权重）上做 RL（[Time-R1](https://arxiv.org/html/2506.10630v1)；[REATS](https://arxiv.org/pdf/2608.10149)），不能当作 RL 适用于 TimesFM 的证据。与 TimesFM 关系最近的 PostTime 让 TimesFM-2.5 出数值预测、Gemma-3-4B 作为文本上下文修订器，先 SFT 再 GRPO：TimesX 上 nMSE 从 0.729（ID）降到 SFT 后 0.650、SFT+RL 后 0.638，**大头来自 SFT，RL 只在其上再加 ID 约 1.8%、OOD 约 4.2%**，而且收益来自 TimesFM 看不到的文本信息（[arXiv 2605.29401](https://arxiv.org/html/2605.29401v1)）。

直接在数值预报器上做 RL 的只有约三篇。TimeRFT 以有原生似然的 MOIRAI-MoE 为策略，每个上下文采样 G=8，报告相对 TimeSFT/TimeLoRA 平均 MSE 好约 10.17%；但**它的 SFT 基线用 NLL 训练、用 MSE 评估**，组内还插入真值作为最高奖励参考，低数据（UCI Air Quality 5%）时 RFT 反而更差，训练时间在 G=8 时是 SFT 的约 1.7 倍、G=24 时约 3.6 倍（[arXiv 2605.00015](https://arxiv.org/html/2605.00015)）。Cazaux 等用 GRPO 微调 iTransformer，MSE 只从 0.202 到 0.198、0.120 到 0.118、0.124 到 0.124，CMAPPO 把 MSE 搞到 0.324，作者警告「微调可能无法改进一个已经很强的模型」（[arXiv 2603.20063](https://arxiv.org/html/2603.20063v1)）。没有任何一篇把 RL 与「用同一个指标做监督微调」放在一起比，而这恰恰是唯一有意义的比较；也没有任何 RL 工作用过 TimesFM 或任何只有分位头的模型。

机理上 RL 在这里处于劣势，有三个原因。第一，TimesFM 的头输出 9 个确定性分位数，不是密度；要当策略，得从分位函数采样（区间内密度分段常数、尾部要临时外推，策略梯度会为了奖励推拉分位间距、破坏校准，逐步独立采样还会生成 192 步的白噪声路径），或者换一个高斯/混合头并重新热身。第二，**南网日分对预测是几乎处处可微的**，路径梯度一次前后向就给出精确梯度；GRPO 用 G=8 个标量奖励估计 192 维方向，是同一个梯度的带噪零阶估计，得分函数估计量的高方差是 Mohamed 等综述的核心论点（[JMLR 2020](https://www.jmlr.org/papers/v21/19-346.html)），Ilyas 等也发现实际策略梯度估计与真实梯度相关性很差（[arXiv 1811.02553](https://arxiv.org/pdf/1811.02553)）。第三，RL 最大化的是「随机样本的期望分」，而生产上打分的是决策层输出；对 1 − RMSE 这种凹奖励，E[S(a)] < S(μ)，策略梯度会系统性把分布宽度压向 0，这正是 TimeRFT 要额外加「变化性奖励」去补的过平滑症状。

**DPO** 需要策略的对数似然，分位头没有；而在有真值时，偏好对只是把监督信号重新编码成排序，丢掉了误差的幅度和方向。检索到的唯一「时序 DPO」是一个用合成偏好数据的业余库（[nanoDPO](https://nanodpo.readthedocs.io/en/stable/README.html)），没有同行评审的预报研究。RLHF 式奖励模型在这里只会去重学一个已知的闭式公式。

**真正该做的「奖励微调」是梯度式的指标对齐。** Beichter 等用 LoRA/DoRA（r8、lr 1e-4、5 epoch）在 Moirai 上以 5 个代理网络近似的日调度成本为损失，梯度只更新适配器，日均成本 €12.75，最佳 MSE 微调 €14.08，零样本 €15.99，相对 MSE 微调好 **9.45%**，同时 MSE/MAE 变差（[arXiv 2503.01936](https://arxiv.org/html/2503.01936v1)）。Gneiting 的一致性理论说明平方误差引出的是均值，pinball 引出的是分位数，报告的泛函与指标错配会导致「严重误导的推断」（[arXiv 0912.0902](https://arxiv.org/pdf/0912.0902)）；Hirsch 与 Ziel 则提醒，按决策指标优化可能奖励失准的分位数（[arXiv 2604.19580](https://arxiv.org/pdf/2604.19580)）。结合 §1 的代码事实：M5 的 p* 已经是南网加权平方误差下的 Bayes 点，所以剩下的错配只在「分位数本身在高权重区域（低出力、权重 1/max(y, 0.2·cap)² 大的时段）校准得够不够」。做法是 L = pinball(9 档) + λ·`nanwang_r2_loss`(p*(q), y)：pinball 保住校准，南网项把高权重区域的点预测拉正，p* 对分位数可微，fp32 下没有障碍。期望收益要比 Beichter 的 9.45% 小得多，因为他们的目标成本离 MSE 很远，而南网指标本身接近相对 RMSE；以 M8 上 p* 的 +1 分为先验上限比较合理。

RL 或零阶方法真正有位置的地方只有两处：带真实动态的序贯决策（储能调度、报价），以及指标里真有不可平滑的阈值（例如低于 85% 才计罚的日考核）。即便如此，务实的做法也是对冻结模型上的少数决策层参数做网格搜索或 CMA-ES，而不是对 TimesFM 权重做 RL；价值导向的预测组合也是直接按决策成本做优化，不用 RL（[arXiv 2501.16086](https://arxiv.org/html/2501.16086v1)）。

### 3.6 协变量适配器、ICF、测试期适配与混合：前两者基本用不上，后两者便宜且有证据

**协变量适配器。** ChronosX 用输入/输出注入块给不支持协变量的骨干外挂协变量（[arXiv 2503.12107](https://arxiv.org/abs/2503.12107)），UniCA 在冻结骨干前后做注意力融合（[arXiv 2506.22039](https://arxiv.org/html/2506.22039v1)）。它们解决的是「骨干没有原生协变量」的问题，而 TimesFM-3 的设计与 Chronos-2 的组注意力同属「协变量作额外变量 + 跨变量注意力」一类。独立的需求预测研究发现，TTM 的通道混合与 Chronos-2 的组注意力「一致地利用外生特征」，其他方法收益不稳定；但 Chronos-2 在新加坡小时级需求上加满约 30 个特征后 MAPE 反而略差（[arXiv 2602.05390](https://arxiv.org/html/2602.05390v1)）。所以 M5 的协变量策略应该是少而强：预报 GHI、目标单位的模板（历史包络或晴空功率），也许加气温，不要把 NWP 字段全塞进去。

**In-context fine-tuning。** TimesFM-ICF 通过继续预训练，让上下文能装下至多 50 条由可学分隔 token 隔开的示例序列；Monash 上 scaled MAE 为 ICF 0.643、全量 FT 0.663、线性探测 0.676、基座 0.694，而且「相关示例胜过单纯更长的自身历史」（2,048 步历史 0.685 vs 50 个示例 0.643）（[arXiv 2410.24087](https://arxiv.org/html/2410.24087)）。但论文、博客和 README 都没有发布 ICF 权重或代码，它也建立在 TimesFM-1 时代的模型上（[Google blog](https://research.google/blog/time-series-foundation-models-can-be-few-shot-learners/)）。TimesFM-3 没有用分隔 token 训练过，硬拼前几天只会复现长历史基线。可用的替代有三条：把邻站作为额外目标变量放进同一次调用（受 `max_variates=32` 限制，变量轴没有身份）；把按 NWP 相似度检索出的历史日功率作为 past-future 协变量（RAF 显示检索增益随模型变大而增大，Chronos-Mini 连神谕未来都用不上（[arXiv 2411.08249](https://www.arxiv.org/pdf/2411.08249)））；以及把上下文加长到 FETS 观察到的饱和点约 2,000 步（约 3 周）（[FETS](https://arxiv.org/html/2604.22328v2)）。三者里最后一条最便宜。

**测试期适配。** 冻结 TSFM 上的轻量在线校正在文献里一致有效：ELF 用傅里叶域线性模型做闭式岭回归加快慢指数加权，在 Chronos、TTM、TimesFM、Moirai、VisionTS 与 ETT、Weather、Solar 等的每个报告组合上都降低了 MASE，每次更新约 0.38 秒（2 CPU）（[arXiv 2502.12920](https://arxiv.org/html/2502.12920v3)）；TAFAS 在分布漂移下把 Chronos 的误差降低至多 45%（[AAAI-25](https://ojs.aaai.org/index.php/AAAI/article/view/33965)）。光伏专用的 PARA-PV 用冻结 Chronos 作先验，加轻量残差适配器和物理门控的均值/尺度修正，作者认为单独的 TSFM「不适合」光伏（[arXiv 2607.08079](https://arxiv.org/abs/2607.08079)，未读到数字）。日前场景下，TAFAS 所说的「部分观测到的真值」就是昨天的实发对昨天的预测，所以一个按站日更的输出校正器（对 [TSFM 分位数, NWP-GHI, 包络功率, 时段] 做岭回归，或按晴空指数分档的门控尺度/偏移）便宜、不需要梯度、与 LoRA 正交，而且正好补上 RevIN 抹掉的水平信息。

**混合。** 与我们最接近的光伏研究（PVDAQ 单站、15 分钟、GFS NWP）里，日间平均 nMAE 为融合集成 4.315%、LightGBM 4.500%、全量微调 Chronos-2 4.592%、零样本 Chronos-2 7.701%；融合相对 LightGBM 的增益 +0.185 pp 低于作者预设的 0.2 pp 实用阈值，而且只做了 4 小时以内（[arXiv 2609.15035](https://arxiv.org/html/2609.15035)）。ERCOT 评测里 TimesFM 零样本光伏 nMAE 9.25%，全量数据微调后 3.71%，与从零训练的 TimeXer 3.85% 相近，但 RMSE 反而更差（7.02 vs 5.82）；这篇论文的正文与表格有几处矛盾，且没有 GBDT 基线（[arXiv 2604.22077](https://arxiv.org/html/2604.22077v1)）。HEFTCom2024 找到的头部队伍全部用 GBDT，没有一家用 TSFM（[Olauson 等, IJF](https://ideas.repec.org/a/eee/intfor/v42y2026i3p724-735.html)；[GEB 队, arXiv 2505.10367](https://arxiv.org/html/2505.10367v2)）。所以 TSFM 在光伏日前里最可信的角色是「先验 + 集成成员」，LightGBM 基线必须补上，它同时也是 M8 复盘里推迟的 C/D 项。做 stacking 时，训练期的 M5 分位数必须是 out-of-fold 的，否则 LoRA 模型的样本内预测会过于乐观。

### 3.7 哪些只对 LLM 有意义

判断标准是方法的前提是否成立。DPO、RLHF 奖励模型、PPO/GRPO 式对齐，前提是策略输出离散 token、奖励没有闭式可微表达或依赖人类判断；我们有真值、指标闭式可微，前提不成立。Time-LLM/TEMPO 式重编程、指令微调、思维链奖励，前提是 LLM 骨干。GRPO 唯一能在预报系统里站住的场景，是像 PostTime 那样用 LLM 修订器引入 TimesFM 看不到的文本信息（天气公报、限电通知），那是另一套架构，不属于「微调 TimesFM」。反过来，LoRA、soft prompt、线性探测、指标对齐损失、测试期校正这些方法虽然多在 LLM 里首先流行，但在 patch-token TSFM 上都有直接证据，不是「只对 LLM 有意义」。

## 4. M8 的教训逐条落到 M5

| M8 教训（来源：M8 复盘与站内实验） | 对 M5 的含义 | M5 动作 |
|---|---|---|
| 架构变体都在 ±0.6 种子噪声内（3 种子 std 0.37） | PEFT 家族互换、rank 扫描大概率同样在噪声内（FETS 的配置不敏感是独立佐证） | 不跑 DoRA/VeRA/IA3/rank 扫描；预算给协议、靶点和输入 |
| 决策层 p* 比中位数 +1 分，是唯一明显超出噪声的项 | M5 的 p* 已是南网加权平方误差的 Bayes 点；分位数一变，p* 就要重选 | 每个 checkpoint（含 z0）都用 `--decision-yaml d2_pstar_point.yaml` 打分；第 4 阶段加可微南网损失 |
| 水平面 GHI 晴空上限压低跟踪/双面站，还曾悄悄把夜间置零（bug） | g2 的 1.05·p_clear 上限是同一陷阱；g1 的晴空功率协变量经 RevIN 后只剩形状，伤害小于硬上限，但对跟踪站形状仍不对 | g2 保持默认关；目标单位模板优先用按站历史包络（M8 h4 的思路），晴空功率只作对照 |
| 生产对所有模型夜间置零；仓库指标全点含夜间、分母下限 0.2·cap | M5 `night_zero: false` 时，夜间小正值会在打分时吃亏，但生产不会 | 主口径用夜间置零打分（与 M8 `diagnose --night-zero` 对齐），同时保留不置零的数字作诊断 |
| 每站固定容量 `cap_mw` 是打分口径；白马湖 54 分是首行容量的指标 bug | 损失与指标都必须用站表容量 | 已是 `normalize_by_cap` + 站表；评估链加断言 |
| 晴空上限曾悄悄改变分数、模型却没变 | FETS 上 PV Hong Kong 的微调在 lr 1e-8 与 1e-5 下同样差约 3 倍，说明是管线差异而非学习（[FETS](https://arxiv.org/abs/2604.22328)） | **第 0 步一致性检查**：l1 run 的 `nanwang_zeroshot` 必须与 z0 run 逐位相同，并与 evaluator 路径对表 |
| 训练在 0.4–0.6 epoch 见顶，之后验证分来回震荡 1.5–3 分 | 按单次验证挑点等于挑噪声 | 开 `ema_decay`（0.999 起）、`smooth_k: 3`、3–5 种子，按种子中位数报告 |
| 小学习率（1e-4）、EMA、5 种子是从零训练的处方 | 对 4M 可训参数的 LoRA，文献里 LoRA 用 1e-6–1e-5（Amazon 默认 1e-6，负荷研究 1e-5），Google 用 1e-4 | LoRA lr 扫 {1e-5, 3e-5, 1e-4} |
| m8_all 切分泄漏了 M1–M4 的状态 | 时间块切分才可信 | 只用 m8_v1；报告 seen / unseen 站分开的分数 |
| 历史日形包络是剩下的杠杆之一 | M5 在无坐标的国能和煦比 M8 高 12.2，说明 TimesFM 自己会从历史学日形；把包络显式给它，可能放大这个优势 | 历史包络功率进 past-future（第 3 阶段） |
| LightGBM 基线一直缺 | 文献里 GBDT 是光伏日前的标杆 | 第 6 阶段补上，并用作 stacking 底座 |
| M8 集成 +0.3–0.5 | M5 与 M8 的误差结构不同（历史驱动 vs 协变量驱动） | M5（零样本或 LoRA）作为 M8 集成成员或 d3/d4 提示通道 |

## 5. 分阶段改进方案：按证据强度与成本排序

**噪声带的定义。** M5 还没有自己的种子方差，所以第 0 阶段先用 l1_lora_r8 的 3 个种子测出成对差的标准差 σ_pair，取 δ = max(0.6, 2·σ_pair)；0.6 是 M8 的经验噪声上限。需要重训的改动，采纳条件是 3 种子均值增益 ≥ δ、至少 2/3 个种子为正、unseen 站不比基线差超过 0.3。只动决策层、不重训的改动在同一 checkpoint 上成对比较，噪声小得多，采纳条件是均值增益 ≥ 0.3 且日块 bootstrap 的 95% 置信区间不含 0（日块 bootstrap 加 DM 检验的做法见 [HKUST 光伏论文仓库](https://github.com/lorenzospolti/solar-pv-forecasting)）。所有比较都在 m8_v1、夜间置零、站表容量的同一口径下进行，并同时报告逐站增益分布，因为文献显示微调在零样本差的序列上收益大、在零样本强的序列上可能伤分（FETS 的增益与零样本难度 Spearman r = 0.39（[FETS](https://arxiv.org/abs/2604.22328)））。

| 阶段 | 实验 | 对应 M8 教训 | 成本 | 进入下一阶段 / 采纳条件 |
|---|---|---|---|---|
| **0 口径与基线** | z0_zeroshot ×1、l1_lora_r8 ×3 种子（m8_v1）；检查 l1 第 0 步分与 z0 逐位相同、torch 与 evaluator 路径对表；夜间置零与不置零两套分数；seen/unseen 分开 | 晴空上限 bug、白马湖首行容量 bug、m8_all 泄漏 | 1 轮 | 一致性检查不过就停下修管线。得到 σ_pair 与 δ。若 l1 − z0 < δ，LoRA 在现设置下不成立，但继续第 1–2 阶段再判 |
| **1 决策层（不重训）** | z0 与 l1 上分别比较 median、p*、按步 p*（`by_step`）、`shrink_factor` | p* +1 分 | 半天 | 按「不重训」标准采纳；之后每个 run 都默认按 p* 选点与报告 |
| **2 训练协议** | LoRA lr ∈ {1e-5, 3e-5, 1e-4} × `ema_decay` 0.999 × `smooth_k` 3；head 冻结 vs 解冻；线性探测对照（只训 head + 输入 ResBlock） | 小 lr、EMA、多种子；变体在噪声内 | 1–2 轮 | 选 3 种子中位数最好的配置作为新基线。**终止条件**：若最佳 LoRA − z0 仍 < δ，M5 停在「零样本 + 决策层 + 第 6 阶段校正器」，权重微调的预算转给 M8 与 LightGBM |
| **3 给信息、改靶点** | （a）历史包络功率作 past-future 协变量（g1 晴空功率作对照）；（b）上下文 672 → 1,344 → 2,016；（c）LoRA 靶点加输入 ResBlock，再加 FFN（all-linear）；（d）诊断：只挂 var_attn vs 只挂 seq_attn | 历史日形包络；水平 GHI 晴空先验的教训 | 2 轮 | 每项单独按 δ 判；跟踪/双面站与无坐标站单独看 |
| **4 指标对齐损失** | L = pinball + λ·`nanwang_r2_loss`(p*(q))，λ ∈ {0.1, 0.3, 1}；同时监控 10%/90% 分位覆盖率 | p* 的 +1 说明指标错配真实存在 | 1 轮 | 增益 ≥ δ 且覆盖率偏离名义值不超过 5 个百分点才采纳 |
| **5 结构与容量** | 全量或后 4 层微调，lr ∈ {1e-6, 1e-5}，配 EMA、早停，可选 LP 热启动与经验回放；K=2–3 簇 LoRA（跟踪/固定或地区）；PaCTS 式 soft prompt（主要看 unseen） | 加参数在 M8 里不涨分，所以放在最后 | 2–3 轮，V100 fp32 最贵 | 只有在第 2–4 阶段饱和后才开；全量微调必须同时报告 unseen |
| **6 事后与混合** | 站级日更输出校正器（ELF/XReg 式岭回归，或按晴空指数分档的门控）；LightGBM 全局基线；以 out-of-fold M5 分位为特征的 stacking；零样本 + LoRA + M8 集成 | 推迟的 LightGBM 基线；集成 +0.3–0.5；refit 模式 | 各半天到 1 轮 | 校正器与集成都按「不重训」标准判；LightGBM 给出 M5 与 M8 的相对位置 |

这个顺序背后的逻辑是：第 0–1 阶段几乎零成本，却能决定后面的数字是否可信；第 2 阶段回答「LoRA 到底值不值」；第 3 阶段动的是 §2 说明的信息瓶颈（NWP 水平被归一化、前瞻读入层被冻结），这是 TimesFM-3 机理特有、M8 无法照搬的杠杆；第 4 阶段只在分位数已经可靠之后才有意义；第 5 阶段成本最高、证据最间接，放在最后。明确不做：GRPO、PPO、DPO、RLHF 奖励模型、DoRA/VeRA/IA3/AdaLoRA/FourierFT、rank 扫描、每站独立 LoRA、Time-LLM 重编程、ICF（没有权重）。

## 6. 风险：许可、参数量与没有先例

**许可证可能决定整件事的价值。** timesfm README 写明 3.0 权重「仅限非商业、非生产用途」，而 2.5 及以前的代码与权重是 Apache-2.0（[timesfm README](https://github.com/google-research/timesfm)；第三方转述见 [pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/13739/google-timesfm-3-forecasting-model-non-commercial)）。M5 已经在 `nanwang_online` 线上零样本运行，如果条款按字面成立，**零样本和 LoRA 版本进入生产都有合规问题**，把 M5 当作 stacking 特征、集成成员或蒸馏教师是否算「生产用途」也需要法务判断。上线前要核对 HF 模型卡的正式条款；如果确实受限，备选路线是 TimesFM 2.5（200M、Apache-2.0、通过 XReg 支持协变量，但协变量不进 Transformer），本报告关于 TimesFM-3 原生协变量通路的分析就不适用于它。

**参数量是 330M 而不是 200M。** 这一更正影响三件事：全量微调的 fp32 优化器状态约 5.3 GB（推算），比按 200M 估计的大 65%；LoRA r8 + head 约 4.0M 可训参数，约占 1.2%；推理与训练的时间成本相应上调。每样本只有 81 个 token，激活不大，所以 V100 上全量微调在显存上可行，但没有实测过 batch 16 下的时间。

**没有任何先例。** 没有公开的 TimesFM-3 光伏微调结果，没有 TimesFM（任何版本）带 NWP 协变量做光伏的微调对零样本比较，没有 TimesFM-3 的协变量消融数字（博客图表没有数值），也没有在南网口径下比较模型类的同行评审研究。本报告里的每个效应量都是从 Chronos-2、Chronos-T5、MOMENT、TimesFM 1.0/2.5 或 M8 迁移过来的推断。

**微调可能伤分。** FETS 上 Chronos-2 对 PV Hong Kong（15 分钟屋顶光伏、上下文 2,000、地平线 192，和我们的设置很像）做 LoRA 后 NRMSE 从 0.198 变成 0.688，训练和验证损失一直在降，测试精度却在变差；德国负荷的区间覆盖率从 0.94 塌到 0.27（[FETS](https://arxiv.org/abs/2604.22328)）。这类退化在 lr 1e-8 下同样出现，所以第 0 阶段的一致性检查是硬前提。分位覆盖率坍塌会直接伤害 p*，因为 p* 依赖整条分位函数。

**未见站可能退化。** MixFT 发现部分按数据集微调的方法「比完全不微调还差」（[arXiv 2603.02840](https://arxiv.org/html/2603.02840v1)），PaCTS 在未见任务上所有权重空间方法都输给零样本（[arXiv 2609.34786](https://arxiv.org/html/2609.34786)）。28 站新增站点时，要保留零样本回退或零样本 + LoRA 集成。

**指标定义本身有不确定性。** 仓库实现用相对误差（分母 max(P_real, 0.2·cap)），而 2018 年南方区域实施细则的检索片段显示按额定容量 Cap、n=96 点计算，85% 以下按 (85% − 日准确率) × Cap × 1h 计罚（[北极星转载](https://mguangfu.bjx.com.cn/mnews/20180118/875022.shtml)，只读到片段），2025 年细则的公式文本没有抽取出来（[NEA 南方监管局](https://nfj.nea.gov.cn/xwzx/tzgg/202502/P020250214585645833212.pdf)）。两种口径下 p* 的权重和指标对齐损失的形式都不同；85% 阈值也意味着改进最值钱的地方是低分日，所以除了均值还应看日分分布。

**NWP 只有两个变量。** M8 上整条 NWP 通路只值 2.6 分，Chronos-2 在真实业务预报（而非完美协变量）下的优势会缩小甚至反转（M8 复盘 §9 引用的协变量噪声研究）。TimesFM-3 再怎么微调，也不能从 GHI 与气温里挖出云量等缺失变量的信息。

## 7. 结论

**哪些方法可行且值得做。** 值得做的按顺序是：决策层 p* 重选，LoRA 学习率/EMA/选点协议，线性探测对照，补信息（历史包络功率协变量、加长上下文、LoRA 覆盖输入 ResBlock），pinball + 可微南网损失，以及事后的站级校正器、LightGBM 基线与集成。可行但只在前面饱和后才值得做的是：小学习率全量或后 N 层微调、分簇 LoRA、soft prompt。可行但不值得做的是：PEFT 家族互换与 rank 扫描（落在噪声内）、外挂协变量适配器（TimesFM-3 已原生支持）、每站独立 LoRA（有伤分证据）。GRPO、PPO、REINFORCE、RLHF 奖励模型在技术上能做，但都被直接对指标反向传播严格支配；DPO 和 Time-LLM 式重编程的前提只在 LLM 里成立；ICF 没有可用权重。

**理解上的变化。** 第一，「选哪种微调方法」是二阶问题，一阶问题是三件 M8 已经付过学费的事：口径一致、决策层、模型拿到什么信息。第二，M5 的 p* 已经是南网损失下的 Bayes 最优点，这把「指标对齐」从「换训练范式（RL）」降成了「让分位数在高权重区域更准」，后者用一项可微损失就能做。第三，TimesFM-3 的逐变量 RevIN 把 NWP 的绝对水平挡在骨干之外，这是 M5 特有、M8 没有的瓶颈，也说明最有希望的改动在输入侧和输出侧（目标单位模板、事后水平校正），而不在注意力里多挂几个秩。第四，M5 相对 M8 的独特价值是从历史学日形（国能和煦 +12.2），它作为 M8 的集成成员或提示通道，可能比单独把 M5 磨到最好更值钱。最后，许可证条款可能直接决定 M5 能否进生产；在大规模投入微调之前，应先把这件事确认清楚。
